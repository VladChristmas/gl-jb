## 2. Визуальные дефекты

### P1-UX-1. Три раздела из нижней мобильной навигации ведут на 500-страницу

- **Страницы:** `/admin/complaints` (пункт «Жалобы»), `/admin/analytics` («Аналитика»), `/admin/weekly_report` («Ещё → Еженедельный отчёт»).
- **Фактически:** HTTP 500, страница «500 — Ошибка сервера» с кнопкой «На главную». На 390/430/768 — одинаково.
- **Ожидаемо:** рабочие разделы.
- **Влияние:** 2 из 7 пунктов основной мобильной навигации сломаны.
- **Скриншоты:** `adm_admin_complaints.png`, `vp390_admin_complaints.png`, `adm_admin_analytics.png`, `adm_admin_weekly_report.png`.
- **Подробности и причина:** см. `GL_JB_FUNCTIONAL_AUDIT.md` (F-01…F-03).

### P2-UX-1. Таблицы `/admin/orders` и `/admin/photos`: колонки узкие, ID переносится по одной цифре на строку

- **Страницы:** `/admin/orders` (колонка «№»), `/admin/photos` (колонка «№»).
- **Фактически:** ID `971` отображается вертикально как `9 / 7 / 1`; дата `2026-10-06 16:54` ломается как `2026-10-06 16 54:29…`; статус-бейдж «Ожидает фото» рвётся на «Ожид да фото». На 1366px и 768px.
- **Ожидаемо:** ID и дата в одну строку (min-width колонки, `white-space: nowrap`), бейдж без переноса.
- **Причина:** ширина колонок задана grid/fixed-долями без min-width; текст переносится посимвольно.
- **Скриншоты:** `adm_admin_orders.png` (строки 971, 970, 969…), `adm_admin_photos.png`.

### P2-UX-2. Технический мусор в колонке «Описание» заказа

- **Страницы:** `/admin/orders`, `/admin/photos`, `/admin/orders/952/photos`.
- **Фактически:** описание выглядит как `czf: МОК Бишкек 14:1; confirmed_at: 3.10.26 08:00; delivery_started: 3.10.26 08:00; sla: 15; sum: 1777` — служебные поля импорта, не пользовательский текст.
- **Ожидаемо:** человекочитаемое описание (адрес/подтема), технические поля — в карточке заказа под сворачиваемым блоком или во вторичном тексте.
- **Скриншоты:** `adm_admin_orders.png`, `func_order_photos.png`.

### P3-UX-1. Тач-цели меньше 44px

- **Замер (computed, viewport 1366):** переключатель темы `☀Светлая 83×26`, `☾Тёмная 75×26`, `⚙Системная 97×26`; логотип `164×22`; многие кнопки высотой 37–39px (`‹ Назад`, фильтры «День/Неделя/Месяц»).
- **Норма (бриф, GL_JB_RULES):** тач-цели ≥ 44px.
- **Комментарий:** на десктопе критично мало; на мобильном (390) переключатель темы сворачивается в компактное меню, но его кнопка-триггер тоже мала.
- **Рекомендация:** `min-height: 44px; min-width: 44px` для кнопок/ссылок в header и фильтрах.

### P3-UX-2. Пустой график «Заказы по дням» на дашборде

- **Страница:** `/admin/` → карточка «Заказы по дням».
- **Фактически:** только подпись даты `2026-10-06`, столбцов/линии нет (для единственной точки sparkline не рисуется).
- **Ожидаемо:** точка или заглушка «Мало данных для графика».
- **Скриншот:** `adm_admin.png`.

### P3-UX-3. Заглушка «Динамика жалоб — в разработке»

- **Страница:** `/admin/` → карточка «Жалобы по дням».
- Постоянная заглушка на главном экране — выглядит как нерабочая функция.

### P3-UX-4. Пустая секция «Лучшие сборщики» на дашборде

- **Фактически:** «Нет данных о сборщиках» при 971 заказе (в данных production нет сборщиков с подтверждённой активностью за период). Если причина в фильтрации периода — стоит проверить логику.

### P3-UX-5. Нативный file input без локализации

- **Страницы:** `/admin/upload_excel`, `/admin/import_excel`, `/admin/operational_analysis`.
- **Фактически:** `Choose File | No file chosen` (английский, зависит от ОС/браузера).
- **Рекомендация:** кастомный label («Выберите файл…») поверх `input[type=file]`.

### P3-UX-6. Утечка внутреннего пути в «Хранилище»

- **Страница:** `/admin/` → «Хранилище → ПУТЬ: `/app/uploads`».
- Внутренняя структура сервера не должна показываться в UI (достаточно размера и количества файлов).

### P3-UX-7. Страница 500: кнопка «На главную» ведёт не туда, куда ждёшь

- Для админа «На главную» = `/` → redirect `/admin/` (ок), но кнопка не даёт пути назад к рабочему разделу. Мелочь: добавить «Повторить» + ссылку на предыдущую страницу.

## 3. Адаптивность (5 viewport)

Прогоны: 390×844, 430×932, 768×1024, 1366×768, 1920×1080.

| Проверка | Результат |
|----------|-----------|
| Горизонтальный скролл `scrollWidth > innerWidth` | **Нет ни на одной странице/viewport** (все 20 комбинаций: `hscroll=false`) |
| Таблица → карточки на мобильном | Работает (`/admin/orders`, `/admin/users` превращаются в карточки) |
| Нижняя навигация (bottom-nav) | Присутствует, `body.has-bottom-nav` имеет `padding-bottom: calc(56px + safe-area)` — контент не перекрывается |
| Header на мобильном | Логотип + компактный переключатель темы, «Выйти» — не переполняется |
| KPI-карточки | На 390 — сетка в 2 колонки, читаемо |
| Фильтры «Сегодня/Неделя/Месяц» | На мобильном растягиваются на всю ширину вертикально (занимают ~150px экрана) — приемлемо, но можно в горизонтальный скролл-чип |
| 1920×1080 | Контент центрирован (max-width), лишнего пустого пространства нет |
| Модальные окна | Установка PWA — центральная на десктопе (`func_install_modal.png`), корректно |

**Замечание по скриншотам:** на full-page скриншотах `vp390_admin_users.png`/`vp768_admin.png` нижняя навигация видна «в середине страницы» — это артефакт съёмки fixed-элемента, в реальном viewport она прижата к низу и не перекрывает контент (проверено padding'ом в `style.css:1620`).

**Реальные устройства (Safari iOS / Chrome Android):** не проверялись — эмуляция viewport это не подтверждает. Требуется ручная проверка (см. непроверенные сценарии).

## 4. Типографика и иерархия (что хорошо)

- Единый `h1` на странице, чёткая иерархия `h1 → h2/h3`.
- KPI-карточки: крупные числа (32px+), подпись серым 12–13px — хорошо читается.
- Тёмная тема работает (замер: `body bg rgb(29,29,31)`), переключение без JS-ошибок (`func_dark_theme.png`).
- Консоль чистая: 0 JS pageerror на всех страницах; единственная ошибка консоли — resource 500/404.
- Пустые состояния оформлены («Фото пока не загружены», «Нет данных о сборщиках», «Пока нет загруженных файлов»).
